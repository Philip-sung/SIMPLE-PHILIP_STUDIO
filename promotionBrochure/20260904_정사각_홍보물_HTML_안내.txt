# PHILIP STUDIO 21cm 정사각 프로모션 HTML 안내

== 파일 목록 ==

a. promo-architecture-service.html — 건축 x 외주 (실내건축 · 인테리어 설계 용역) 5장
b. promo-architecture-course.html — 건축 x 강의 (공간 · 건축 강의) 5장
c. promo-it-service.html — IT x 외주 (웹 · 앱 개발 / 기업 AI 도입 용역) 5장
d. promo-it-course.html — IT x 강의 (AI · IT 강의) 5장

네 파일 모두 외부 자원을 참조하지 않는 단일 HTML이다. 인터넷 연결 없이 열리며, 파일 하나만 전달해도 상대방 컴퓨터에서 동일하게 보인다.

== 규격 ==

a. 페이지 210 x 210 mm 정사각. 페이지 크기는 파일 안의 @page 규칙이 지정하므로 인쇄 대화상자에서 용지를 고를 필요가 없다
b. 안쪽 여백 사방 16 mm. 글자는 모두 이 안에 있어 재단에 안전하다
c. 각 장은 210 mm 한 면에 고정되며 내용이 넘치지 않도록 높이를 잠가 두었다
d. 파일당 6장 (표지 1장 + 본문 5장), 합계 24장

== 장별 구성 (한 장에 한 포인트) ==

모든 파일이 같은 여섯 단계를 따른다. 1장은 어두운 바탕의 표지, 2~5장은 흰 바탕, 6장은 다시 어두운 바탕이다.

1. 표지 — 트랙의 핵심 문장 하나와 수행자 한 줄
2. WHY — 왜 이 서비스인가. 번호 타일 3~4개
3. 상품 1 — 카드 2~3개. 이름, 대상, 포함 항목 세 줄, 가격
4. 상품 2 — 같은 구조의 카드
5. PORTFOLIO — 실적 사진 격자. 트랙마다 같은 지면을 용역·교육 두 파일에 함께 넣었다
6. 진행 방식 — 7단계 가로 타임라인, 원칙 또는 교재, 큼직한 연락처

건축 x 외주
1. 도면 없이 받은 견적은 애초에 비교할 수 없습니다
2. 시공사마다 말이 다른 이유는 하나, 기준이 되는 도면이 없기 때문입니다 — 비교 · 근거 · 재사용
3. 실측부터 견적설계까지, 한 사람이 연결합니다 — PACKAGE A 45만원~ / B 140만원~ / C 350만원~
4. 지어진 뒤에도, 판단의 기준은 계속 필요합니다 — 점검 · 검증 · 자문 각 30만원~
5. 범위를 문서로 확정한 뒤에 시작합니다 — 외주 7단계

건축 x 강의
1. 대신 판단해 드리는 것이 아니라, 판단의 기준을 옮겨 드립니다
2. 내 공간을 남의 말에만 의존하지 않으려면, 최소한의 기준이 내 쪽에 있어야 합니다 — 읽는다 · 본다 · 정한다
3. 먼저 그려 보고, 그 다음 읽습니다 — LEVEL 01 · 02
4. 공사 중 무엇을 언제 봐야 하는지, 어떤 말이 나오면 멈춰야 하는지 — LEVEL 03 · 04
5. 회당 2시간, 오프라인 1:1 대면 — 교육 7단계

IT x 외주
1. 만드는 사람과 운영하는 사람이 같습니다
2. 경력의 길이가 아니라, 지금 운영 중인 서비스가 증명합니다 — 시리즈C · 앱 3종 · LLM 과금 · Kubernetes
3. 범위를 문서로 확정한 뒤, 고정가로 만듭니다 — STANDARD 90만원~ / DELUXE 240만원~ / PREMIUM 600만원~, 설치형 앱 · 리테이너
4. 도입할지를 묻기 전에, 어디에 쓸지를 먼저 정합니다 — 진단 150만원~ / 로드맵 / 구축 300만원~
5. 문서로 시작해서, 문서로 끝냅니다 — 외주 7단계, 고정가 · 선금 50% · 사후 30일

IT x 강의
1. 대신 만들어 드리는 것이 아니라, 판단의 기준을 옮겨 드립니다
2. 도구는 계속 바뀝니다. 원리를 아는 사람의 기준은 남습니다 — 대상 4유형
3. 지도를 그리고, 운영을 배우고, 원리를 봅니다 — LEVEL 01 · 02 · 03
4. 내 업무 케이스로, 내 코드베이스로 진행합니다 — LEVEL 04 · 05 · 06
5. 회당 2시간, 1:1 대면 또는 온라인 — 교육 7단계, 비법노트 · 앱 3종 멤버십 · 사후 Q&A

모든 문구, 가격, 연락처는 brochure-architecture.html 과 brochure-it.html 에서 그대로 옮겼다.
건축 트랙의 법적 고지(업무 범위의 한계, 업무의 성격, 교육의 범위)는 해당 장 하단 작은 글씨로 유지했다. 지우지 않는다.

== 디자인 규칙 ==

a. 색과 형태 언어는 business-cards 와 기존 브로슈어의 브랜드 규칙을 따른다.
   건축은 짙은 그린(#0A3711)과 금색(#C9A227), 직각 모서리, 표지의 얇은 금색 프레임과 재단면 밖으로 확장되는 직선.
   IT는 블루 팔레트(#CEDEF2 ~ #023373), 4 mm 라운드 모서리, 표지 우상단의 원 안 동심 아치.
b. 한 장에 한 메시지. 헤드라인은 두 줄 이내로 잠그고, 그 아래 한 문단만 둔다.
c. 타입 스케일은 일곱 단계(--f1~--f7)만 쓴다. 크기를 늘려 위계를 만들지 않고 굵기와 색으로 만든다.
   --f1 29pt 표지 헤드라인 / --f2 20pt 본문 헤드라인 / --f3 16pt 가격 · 연락처 / --f4 11pt 카드 · 타일 제목
   --f5 9pt 리드 문단 / --f6 7.8pt 본문 / --f7 6.2pt 라벨 · 꼬리말 · 고지
   크기 종류를 줄이고 볼드를 아끼는 것이 절제된 인상을 만든다는 편집디자인 통칙을 따랐다. 그림자 · 그라데이션은 쓰지 않는다.
d. 수직 여백은 4mm 모듈(--u)의 배수만 쓴다. 스무 면이 같은 수직 리듬 위에 놓인다.
e. 인디케이터는 내용보다 작게 둔다. 장식이 커지면 투박해진다.
   타일 번호는 22pt 큰 숫자에서 6.2pt 자간 라벨로, 단계 표식 점은 4.6mm에서 2.4mm로, 제목 아래 표시선은 16 x 0.7mm에서
   13 x 0.5mm로 줄였다. 타일의 태그는 테두리 상자를 없애고 자간 라벨만 남겼다. 카드 항목 구분선은 점선에서 실선 헤어라인으로 바꿨다.
f. 카드 문구는 글자수를 맞춘다. 3열 카드는 항목당 한 줄(한글 14자 내외), 2열 카드는 항목당 한 줄(한글 25자 내외)이고
   항목은 카드마다 정확히 세 개다. 대상 설명(who)도 한 줄로 맞춘다. 길이가 들쭉날쭉하면 카드 속이 어긋나 보인다.
   문구를 늘릴 때는 항목 수를 늘리지 말고 같은 자리에서 글자수만 맞춰 바꾼다.
g. 지면은 세 덩어리다. 위에 머리말(엠블럼 · PHILIP STUDIO · 쪽번호), 아래에 꼬리말(연락처), 그 사이에 내용이 온다.
   내용은 .body 의 justify-content:center 로 한 덩어리째 가운데 정렬된다. 제목 · 리드 · 카드가 함께 움직인다.
   개별 요소에 auto 마진을 주면 안 된다. 제목은 위로, 카드는 아래로 갈라져 지면이 위아래로 쏠린다.
   .grid · .folio · .contact 는 모두 고정 여백(9mm)만 쓰고, 남는 높이는 .body 가 위아래로 나눠 갖는다.
   표지도 같다. 처음에는 표지만 justify-content:flex-end 로 글을 아래에 붙였는데 아래 금색 선에 몰려 답답해 보여
   본문과 같은 center 로 통일했다.
   건축 표지의 금색 프레임은 시트 안쪽 여백(16mm)이 아니라 그보다 5mm 바깥인 11mm 에 둔다.
   프레임과 여백이 같은 자리에 있으면 머리말과 꼬리말이 금색 선에 딱 붙는다. 프레임 밖으로 뻗는 연장선의
   -11mm 오프셋도 이 값과 같이 움직이므로 한쪽만 고치지 않는다.
h. 남는 높이를 카드를 늘려 채우지는 않는다. 카드를 늘리면 항목과 가격 사이가 비어 속이 빈 상자처럼 보인다.
   카드끼리는 align-items:stretch 로 같은 높이가 되고, 가격줄만 margin-top:auto 로 카드 안쪽 바닥에 붙어
   카드 높이가 달라져도 가격이 항상 한 선에 놓인다. 이 auto 는 카드 안에서만 쓰는 것이라 위 규칙과 다르다.

== 포트폴리오 지면 (5장) ==

사진은 각 스튜디오의 asset/hero 에서 가져와 줄인 뒤 data URI 로 심었다. 외부 파일을 참조하지 않으므로 html 하나만 전달해도 그대로 보인다.

a. 건축 — asset/hero 의 원본 사진 6장. 파일명의 _BLUR-n · _GRAYSCALE 토큰은 홈페이지 히어로에서 화면에 입히는 효과라
   원본 파일 자체는 깨끗하다. 그래서 그대로 잘라 쓸 수 있다.
   실은 프로젝트가 겹치지 않도록 골랐다. 공동집배송센터 외관 · 하역부, 관리업무시설, 스마트쉼터, 서울의료원 로비, 여의도성모병원.
b. IT — asset/hero 의 mp4 5편에서 대표 프레임을 한 장씩 뽑아 썼다. 같은 폴더의 01~06.png 스틸은 M-Raum 이 네 장을 차지해
   프로젝트별로 한 장씩 고르기 어려웠다. 영상 프레임을 쓰면 manifest 의 프로젝트명과 정확히 1:1로 맞는다.
   여섯 번째 칸은 사진 대신 STACK 글 칸이라 3 x 2 격자가 빈칸 없이 찬다.
c. 모두 3:2 중앙 크롭 · 가로 680px(21cm 3열 기준 300dpi) · JPEG 품질 80 이다. 건축 파일이 약 400KB, IT 파일이 약 175KB 다.
d. 사진을 바꾸려면 html 안의 해당 <img src="data:image/jpeg;base64,...">를 새 data URI 로 갈아 끼운다.
   원본을 그대로 넣으면 파일이 수 MB로 불어나므로 반드시 위 규격으로 줄여서 넣는다.
e. 엠블럼은 명함(business-cards)의 SVG 도형을 그대로 옮긴 인라인 SVG다. 이미지 파일이 아니므로 크기를 키워도 깨지지 않는다.
   건축은 얇은 금색 프레임과 재단면 밖으로 연장되는 직선, IT는 원 안의 동심 아치 세 겹이다.
   색은 --e1(안쪽·테두리) --e2(가운데) --e3(바깥) 변수로 받는다. 어두운 면에서는 --ed1~--ed3 이 대신 적용된다.
   아치 세 겹은 밝은 면에서 안으로 갈수록 어두워지고, 어두운 면에서는 안으로 갈수록 밝아져야 세 겹이 구분된다.
   처음에 CSS 도형(border + 가상요소)으로 흉내냈을 때는 건축 프레임의 연장선이 두 방향만 그려지고
   IT 아치가 한 덩어리로 뭉개져서, 명함 좌표를 그대로 쓰는 SVG로 바꿨다.
f. 서체는 Noto Sans KR 이다. 이 PC에 설치된 가변 글꼴이라 200~900 굵기가 모두 실제 굵기로 나온다.
   맑은 고딕은 200~500이 한 굵기로 뭉개지고 라틴 문자 품질이 떨어져 대체용으로만 남겨 두었다.
   본문은 350, 카드 제목과 라벨은 700, 헤드라인과 가격은 800 을 쓴다. 가변 글꼴이 아닌 PC에서는
   이 단계가 두세 단계로 줄어들지만 위계는 유지된다.

== 인쇄 방법 ==

1. 브라우저(Chrome, Edge 권장)로 html 파일을 연다
2. 상단의 "인쇄 · PDF로 저장" 버튼을 누르거나 Ctrl+P 를 누른다
3. 대상: "PDF로 저장"을 고른다. 페이지 크기는 210 x 210 mm로 자동 지정된다
4. 배율: 100% (맞춤 축소 아님)
5. 여백: 없음
6. 배경 그래픽: 켜기 — 이 항목을 끄면 어두운 표지와 색 카드가 흰색으로 빠진다
7. 저장한 pdf를 인쇄소에 전달한다. 정사각 판형은 일반 프린터 용지에 없으므로 인쇄소 출력을 기준으로 한다

상단 안내바는 인쇄물에 나오지 않는다. 화면에서만 보이는 조작용 막대다.

재단 여유(bleed)는 포함하지 않았다. 인쇄소가 사방 3 mm 여유를 요구하면 style 블록의 @page size와 .sheet 크기를 216 mm로 키우고
.sheet 의 padding 을 19 mm 로 늘리면 된다. 글자는 모두 가장자리에서 16 mm 안쪽에 있어 재단에 안전하다.

== 인쇄 레이아웃에서 건드리면 안 되는 세 가지 ==

한 장이 두 면으로 쪼개지거나 빈 면이 끼는 문제를 잡느라 다음 세 가지를 조정해 두었다. 되돌리면 증상이 다시 나타난다.

a. @media print 블록은 반드시 style 의 맨 끝에 둔다
   .sheet 규칙보다 앞에 두면 명시도가 같아 뒤에 오는 .sheet 규칙에 덮어써진다. 그러면 시트가 210 mm 로 남아
   페이지(209.89 mm)를 넘기고, 장마다 두 면이 된다.
b. 인쇄 시 시트는 209.5 mm 로 줄이고 break-after:page 를 함께 준다
   둘 중 하나만 적용하면 장마다 빈 페이지가 하나씩 더 생긴다. 크기만 줄이면 페이지 경계가 어긋나고,
   페이지 넘김만 주면 넘친 부분이 다음 면으로 흘러간다.
c. 꼬리말(.ft)은 시트 바닥에 absolute 로 붙인다
   플렉스 항목으로 두면 인쇄할 때 다음 면으로 밀려 내려간다. 표지 규칙(.cover .hd, .cover .body)에 .ft 를 다시 넣어
   position:relative 가 되면, left 값이 위치가 아니라 이동량으로 해석되어 꼬리말이 오른쪽으로 밀려 잘린다.
   본문(.body)의 아래 여백 15 mm(표지 20 mm)가 그 꼬리말 자리이므로 함께 줄이지 않는다.
d. 어두운 면은 퍼짐 그림자로 가장자리 틈을 덮는다
   시트를 209.5mm 로 줄여 놓았으므로 209.89mm 페이지의 오른쪽과 아래에 0.4mm 만큼 종이 흰색이 띠로 남는다.
   밝은 면은 표가 나지 않지만 어두운 표지와 마지막 장에서는 흰 테두리로 보인다.
   그래서 인쇄 규칙에 .sheet.dark { box-shadow:0 0 0 3mm var(--p) } 을 두어 같은 색을 상자 밖까지 넓혔다.
   퍼짐 그림자는 자리를 차지하지 않으므로 레이아웃과 페이지 나눔에는 영향이 없다. 이 줄을 지우면 흰 테두리가 돌아온다.
e. 본문이 넘치면 꼬리말 위로 겹쳐 인쇄된다
   .body 는 overflow:hidden 이라 넘친 내용이 잘리지 않고 꼬리말 자리로 흘러든다. 한 장에 카드 3개와
   부가항목 줄(.strip)을 함께 넣으면 그 아래 작은 글씨(.micro)가 꼬리말과 겹친다. IT 외주 3장이 그 경우라
   그 장의 micro 를 빼고 같은 내용을 5장 원칙 블록에 두었다. 내용을 늘린 뒤에는 20면의 꼬리말 위쪽을 눈으로 확인한다.

검증 결과: 네 파일 모두 6면, 209.89 x 209.89 mm, 빈 면 없음, 24면 전부 꼬리말 겹침 없음.
300dpi 로 펼쳐 네 가장자리를 안쪽 색과 대조했을 때 24면 모두 흰 테두리 없음.

== 수정할 때 ==

a. 가격, 실적, 연락처는 html 파일 안의 해당 문구를 직접 고친다
b. 색은 파일 상단 style 블록의 :root 변수만 바꾸면 전체에 반영된다. 라운드 정도는 --r, 단계 표식 모양은 --dot 이다
c. 문구를 늘리면 해당 장이 한 면을 넘길 수 있다. 늘린 뒤에는 반드시 인쇄 미리보기로 그 장이 두 면으로 쪼개지지 않는지 확인한다
