# hero 에셋 폴더 (it-studio)

이 폴더에 넣은 이미지·영상이 페이지 최상단 100vw × 100vh 히어로의 배경 슬라이드로 표시된다.
로더 구현은 [shared/hero.js](../../../shared/hero.js), 스타일은 [shared/hero.css](../../../shared/hero.css)에 있다.

## 지원 형식

- 이미지: `png`, `jpg`/`jpeg`, `webp`
- 영상: `mp4`(H.264 권장), `webm` — 자동으로 음소거·인라인 재생되고, 끝나면 다음 슬라이드로 넘어간다

## 파일명 규칙

- 기본 형식: `01_이름.확장자` — 맨 앞 숫자의 오름차순으로 슬라이드 순서가 결정된다
  - 예: `01_office.jpg` → `02_demo.mp4` → `03_team.webp`
  - 숫자 뒤 이름 부분은 자유 (표시되지 않음)
- 토큰 (파일명에 붙이면 자동 적용, 서로 중복·순서 무관):
  - `_GRAYSCALE`: 회색조 처리
  - `_BLUR-6`: 6px 블러 (숫자 = px 값, 소수 가능)
  - `_TITLE-제목내용`: 우측 하단 슬라이드 번호(`01 / 08`) 왼쪽에 그 제목이 우측정렬로 표시된다
    - 제목은 다음 토큰 직전 또는 확장자 직전까지를 그대로 읽으므로 공백·하이픈·가운뎃점을 써도 된다
    - 화면이 좁아 자리가 부족하면 제목만 말줄임(…)으로 줄고 번호는 항상 온전히 남는다
    - 제목을 붙이지 않은 파일은 그 슬라이드에서 제목 없이 번호만 나온다
  - 중복 예: `03_lobby_TITLE-서울의료원 로비 개선공사_GRAYSCALE_BLUR-4.jpg`
    → 회색조 + 4px 블러 + 제목 "서울의료원 로비 개선공사"

## 규격·용량 권장치

- 이미지:
  - 해상도: 1920×1080 이상 가로형 권장. 비율이 안 맞아도 비율을 유지한 채 화면을 꽉 채우도록 확대(cover)되며, 넘치는 부분은 잘린다
  - 용량: 장당 800KB 이하 권장 (webp 변환 권장). 첫 번째 슬라이드가 가장 먼저 보이므로 01번은 가장 가벼운 파일로
- 영상:
  - 해상도: 1080p, 길이 10~20초 권장
  - 용량: 10MB 이하 권장. 오디오 트랙은 어차피 음소거되므로 제거하면 용량이 준다
  - 영상은 끝나면 자동으로 다음 슬라이드로 넘어간다 (길이에 맞춰 대기, 상한 90초)
  - **faststart 필수**: MP4는 재생 정보(`moov`)가 파일 앞쪽에 있어야 브라우저가 곧바로 첫 프레임을 그린다.
    편집 프로그램이 내보낸 파일은 대개 `moov`가 맨 끝에 있어서, 브라우저가 파일 전체를 다 받을 때까지
    히어로가 검게 남는다. 아래 명령으로 다시 감싸면 화질 손실 없이(스트림 복사) 앞쪽으로 옮겨진다.
    ```
    ffmpeg -i 원본.mp4 -c copy -movflags +faststart 결과.mp4
    ```

## 등록 방법

파일을 이 폴더에 넣는 것이 전부다. 로더는 목록을 얻는 경로를 순서대로 시도하고,
하나라도 성공하면 거기서 멈춘다. 순서는 환경에 따라 다르다.

- 로컬(localhost 또는 `file:`): 디렉터리 목록 → `manifest.json` → GitHub API
  - 폴더의 실제 내용을 가장 먼저 믿으므로, 파일을 넣고 빼기만 해도 새로고침에 바로 반영된다
  - `manifest.json`이 낡아 있어도 로컬에서는 무시되므로 신경 쓸 필요가 없다
- 배포본(GitHub Pages): `manifest.json` → GitHub API → 디렉터리 목록
  - GitHub Pages는 디렉터리 목록을 주지 않으므로 `manifest.json`을 먼저 읽는다
  - `manifest.json`이 없으면 GitHub API로 커밋된 파일을 조회하므로, manifest 없이도 동작한다

주의: `manifest.json`은 만들어 둔 시점의 목록이라 파일을 넣고 빼면 곧 낡는다.
배포본은 이 파일을 먼저 믿으므로, **에셋을 바꿨으면 반드시 아래 "배포 전 한 줄"을 다시 실행**하거나
`manifest.json`을 지워서 GitHub API 조회로 넘기면 된다.

### 로컬에서 미리 보기

리포 최상단에서 로컬 서버를 띄우고 접속한다. 이 경우 디렉터리 목록을 먼저 읽으므로
파일을 넣고 새로고침하면 바로 보인다.

```
python -m http.server 8000
```

접속 주소: `http://localhost:8000/it-studio/` (VS Code의 Live Server 확장도 동일하게 동작한다)

`index.html` 파일을 더블클릭해 `file://`로 여는 방식은 브라우저가 로컬 파일 조회를 막기 때문에
커밋·푸시된 에셋만 보이고, 아직 커밋 안 한 파일은 보이지 않는다.

### 배포 전 한 줄

에셋을 넣거나 빼거나 이름을 바꿨으면, 커밋 전에 리포 최상단에서 아래를 실행해
`manifest.json`을 현재 폴더 내용으로 다시 만든다. 그리고 에셋과 함께 커밋한다.
manifest가 있으면 배포본이 외부 API 호출 없이 즉시 떠서 더 빠르고 안정적이다.
(이 단계를 건너뛰면 배포본이 낡은 목록을 읽어, 지운 파일을 찾다가 히어로가 비어 보인다)

```
node shared/gen-hero-manifest.js
```

manifest를 손으로 적어도 된다. 형식은 파일명 배열이다.

```json
["01_office.jpg", "02_demo.mp4", "03_lobby_GRAYSCALE_BLUR-4.jpg"]
```

## 에셋이 하나도 없으면

- 페이지는 기존의 그라데이션 배경 히어로로 표시된다 (오류 아님)
